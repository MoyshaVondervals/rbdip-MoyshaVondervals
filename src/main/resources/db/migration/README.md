# Миграции

`V1__init.sql` — начальная схема, эталон, не редактируется.

Свои миграции добавляйте следующими номерами: `V2__...sql`, `V3__...sql` и т.д.
(стандартная схема именования Flyway: `V<версия>__<описание>.sql`).

## ЛР3

1. V3 добавляет поля и двустороннюю запись.
2. V4 переносит имена. По умолчанию `FLYWAY_TARGET=4`.
3. Заменить все экземпляры приложения новой версией.
4. Запустить с `FLYWAY_TARGET=5`: V5 удалит старое поле.

Имя делится по первому пробелу без потери исходной строки.
При `lock_timeout` повторить миграцию после освобождения блокировки.

```bash
mvn -Dtest=CustomerNameTest,CustomerNameMigrationTest,CustomerNameApiLoadTest test
```

Эталон ЛР3 несовместим с V2: читает удалённую `orders.customer_full_name`.
Для проверки ЛР3 нужны база V2 и `customers.customer_full_name`.
